## Phase 2: progress sync (db + user) - `js/ai-sync.js`
- [x] Mirror only; localStorage is primary. Needs both `db` and `user` (id non-null).
- [x] Docs: `data/users/<id>/progress` and `data/users/<id>/progress-code` (code of each problem). NOTE: the spec said `.../progress/main`, but the db
      path grammar needs an EVEN segment count for a document (5 segments = collection), so the doc is `progress`.
- [x] Per-item `{ts, v}`; newest ts wins per item; xp / activity take the max; mock tests are united. Items get `ts = now` when their content hash changes.
- [x] Writes: only when something changed, debounce 4 s, never more than one write per 10 s, one at a time (read -> merge -> write); pristine state is not written.
- [x] Pull on load and when the tab becomes visible again (max once per 60 s). Errors: `invalid_argument`/`not_granted`/`capability_*`/`revoked` stop sync for the view; others wait for the next change.
- [x] Reset deletes the remote docs; Import marks all items as newly changed.

## Mock shim switches (`?ai=mock`)
`mockfail=<code>` all calls reject with that code; `mocknull=1` use("sample") -> null; `mocktools=1` limits().tools; `mockslow=<ms>` stream speed; `mockdb=0` no db; calls recorded in `window.__aiMock`.

## Known gaps
- Never tested against the real Claude runtime (consent dialog, real streaming, real db limits); only the contract-faithful mock.
- Each db doc is limited to 256 KiB: the writer drops the biggest items first if the doc is too large (very large code collections could be partly unsynced).
- Deletions are not synced (except Reset). Remote changes found after load update local state but a page already open is only re-rendered on path/progress/review/problems/settings.
- The `run_python` tool cannot cancel a running snippet before its 5 s limit (Stop aborts the call; the worker is restarted on timeout).
- Drill interviewer state (question count) is kept in localStorage with the chat; clearing the chat resets it.
- On static hosts the worker's `split.json` probe is one extra 404 request when the first Python run starts.
